# Local-First RAG Document Q&A System with Retrieval Evaluation Pipeline

Ask questions over your own PDF, Markdown and text files and get **answers with inline citations** (`[1]`, `[2]`) that point to the source file and page.

Embeddings and the vector database run **locally and free**. The answer is generated by a local **Ollama** model (free) or **Claude** (API key), switchable from one config file. The project also includes an **evaluation pipeline** (Hit Rate@k, MRR, keyword coverage) so every tuning change is measured instead of guessed.

## Key Features

- **Multi-format ingestion:** PDF (page-aware), Markdown and TXT files.
- **Boundary-aware chunking:** a sliding window that prefers to cut at paragraph, line, sentence, then word boundaries, with overlap to keep context across chunk edges.
- **Idempotent re-ingestion:** re-running ingest replaces a file's old chunks, so there are no duplicates.
- **Grounded answers with citations:** the LLM answers only from retrieved context and cites sources as `[1]`, `[2]` with file name and page number.
- **Hallucination guard:** a cosine-similarity threshold (`MIN_SCORE`) blocks off-topic questions before they reach the LLM.
- **Pluggable LLM:** Ollama (free, local) or Claude (Anthropic API), selected in `.env`.
- **Built-in evaluation:** Hit Rate@k, MRR and keyword coverage, appended to `logs/eval_history.csv` together with the settings used.
- **Query logging:** latency, top similarity score and sources for every query in `logs/queries.jsonl`.
- **Fully configurable:** chunk size, overlap, top-k, score floor and models are all environment variables.

## Architecture

```
INGEST (once)                          QUERY (every question)
docs/*.pdf|md|txt                      question
   -> chunk (800 chars, 150 overlap)      -> embed question
   -> embed each chunk                    -> top-k similar chunks from ChromaDB
   -> store in ChromaDB                   -> similarity below MIN_SCORE? -> "not found"
                                          -> prompt = rules + numbered chunks + question
                                          -> LLM answers with [1] [2] citations
                                          -> log latency, score and sources
```

## Setup

```bash
# 1. Clone
git clone https://github.com/YOUR-USERNAME/rag-document-qa.git
cd rag-document-qa

# 2. Create a virtual environment
python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # macOS / Linux

# 3. Install dependencies
pip install -r requirements.txt

# 4. Create your config file
copy .env.example .env          # Windows
# cp .env.example .env          # macOS / Linux
```

### Choose an LLM

**Option A: Free, local (Ollama)**
```bash
ollama pull llama3.2
```
In `.env`:
```
LLM_PROVIDER=ollama
LLM_MODEL=llama3.2
```

**Option B: Claude (API key)**

In `.env`:
```
LLM_PROVIDER=anthropic
LLM_MODEL=<claude model name>
ANTHROPIC_API_KEY=your_key_here
```

> The first run downloads the embedding model (about 90 MB). After that, add `HF_HUB_OFFLINE=1` to `.env` for faster, quieter startup.

## Usage

```bash
python ingest.py                  # after adding files to docs/
python rag.py                     # interactive chat
python rag.py "your question"     # one-shot question
python eval.py                    # retrieval quality: Hit Rate@k and MRR
python eval.py --answers          # also checks keywords in generated answers
```

## Configuration

All settings live in `.env` and can be overridden without touching the code.

| Variable | Default | Purpose |
|---|---|---|
| `CHUNK_SIZE` | 800 | Characters per chunk |
| `CHUNK_OVERLAP` | 150 | Characters shared between neighbouring chunks |
| `TOP_K` | 4 | Chunks sent to the LLM |
| `MIN_SCORE` | 0.2 | Similarity floor; below it the system answers "not found" |
| `EMBED_MODEL` | all-MiniLM-L6-v2 | Embedding model (try `BAAI/bge-small-en-v1.5`) |
| `LLM_PROVIDER` | ollama | `ollama` or `anthropic` |
| `LLM_MODEL` | llama3.2 | Model name for the chosen provider |
| `HF_HUB_OFFLINE` | (unset) | Set to `1` after the first download to skip Hugging Face network calls |

**Tuning loop:** change ONE setting, re-run `python ingest.py` if it affects chunks, run `python eval.py`, and keep the change only if `logs/eval_history.csv` improves.

## Problems Faced and Solutions

| # | Problem | Root cause | Solution |
|---|---|---|---|
| 1 | The model replied "I don't know" even though the correct chunk was retrieved (score 0.53) | An overly strict system prompt combined with a small local model | Separated retrieval from generation to prove retrieval was working, then rewrote the prompt to allow combining passages while still forbidding outside knowledge, increased `TOP_K`, and tested a larger model |
| 2 | Off-topic questions (for example "what is database") risked made-up answers | No relevance check before generation | Added a cosine-similarity gate (`MIN_SCORE`); out-of-scope queries return a fallback without calling the LLM, saving latency and compute |
| 3 | Slow startup and "unauthenticated requests to the HF Hub" warnings on every run | The embedding model re-checked Hugging Face on each load | Cached the model locally and enabled offline mode with `HF_HUB_OFFLINE=1` |
| 4 | Long traceback (httpx / httpcore thread lock) after pressing Ctrl+C | `huggingface_hub` closes its HTTP session at interpreter exit while the program is being interrupted | Diagnosed it as harmless shutdown noise from a third-party library; offline mode and a clean exit remove it |
| 5 | Fixed-size chunks cut sentences in half and hurt retrieval | Naive character splitting | Built a boundary-aware sliding-window chunker with overlap |
| 6 | Duplicate chunks after editing and re-ingesting files | Append-only inserts | Deterministic chunk IDs (`source::page::chunk`) plus delete-by-source before upsert |
| 7 | No way to know whether a tuning change helped | No evaluation | Wrote `eval.py` with Hit Rate@k, MRR and keyword coverage, logged to CSV with the settings used |
| 8 | Answers could not be traced back to sources | No location metadata | Extract PDFs page by page and store `source` and `page` per chunk, so citations read `file.pdf, p.7` |

## Troubleshooting

| Symptom | Fix |
|---|---|
| "I couldn't find anything relevant in the documents." | Lower `MIN_SCORE`, or the answer is not in `docs/` |
| Vague or wrong answers | Check the Sources printed under the answer. If the right chunk is missing, it is a retrieval problem (tune chunking); if it is present, it is a prompt or model problem |
| "I don't know" despite good sources | Increase `TOP_K`, relax the system prompt, or use a larger model (for example `llama3.1:8b`) |
| PDF returns empty text | The PDF is scanned; run OCR first (for example `ocrmypdf`) |
| Changed `EMBED_MODEL` | Delete `chroma_db/`, temporarily unset `HF_HUB_OFFLINE`, and re-run `python ingest.py` (vectors from different models cannot be mixed) |
| Traceback after Ctrl+C | Harmless Hugging Face shutdown noise; set `HF_HUB_OFFLINE=1` |

## Conclusion

This project covers the full RAG lifecycle: ingestion, chunking, embeddings, vector search, grounded generation and evaluation, all runnable locally at no cost. The main lesson was learning to diagnose **which stage** is failing: in my testing, retrieval found the correct chunk while generation still refused, because of prompt strictness and model size, not retrieval quality. A similarity guard reduces hallucination on out-of-scope questions, and the evaluation loop makes every tuning decision measurable. The modular design makes it straightforward to extend with hybrid search, reranking and an API layer.
